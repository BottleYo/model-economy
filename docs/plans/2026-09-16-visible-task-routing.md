## 2. 路由基础

主责模块：`models.py`、`profiles.py`、`renderer.py`、`config.py`、`lifecycle.py`、`doctor.py`、`cli.py`，以及对应测试。该组有紧密数据依赖，作为一个实施工作包，不按文件机械拆成并发任务。

依次实现：

1. 先加入能失败的 v1/v2 读取、完整 reasoning、角色模型覆盖和拒绝非法数据测试。
2. 实现统一解析对象；角色模型优先于能力模型，reasoning 独立；只允许六个已知角色。
3. 更新渲染和档案；旧参数语法保持，增加明确的角色覆盖参数。
4. 实现 v1 内存兼容及升级迁移，旧安装有效 effort 不变化；加入预览、唯一备份、失败恢复与重复升级零写入。
5. status JSON v1 保持字段树；verify/status 内部核对有效角色模型和 reasoning。导出排除机器/项目数据。
6. 全部在临时测试目录运行生命周期流程；真实用户安装不用于迁移开发测试。

完成条件：用户无需更换旧档案即可升级；保留旧模型和有效推理强度；新安装默认 implementer medium、explorer low；配置冲突、非法工件和回滚路径可验证。

## 3. Skill 派发契约与可见任务试点

主责：`cost-aware-development/SKILL.md`、`references/routing-policy.json`、上下文契约、角色矩阵、路由示例、质量门，以及新增按需读取的可见任务参考/工作包模板和契约测试。

该工作包等配置解析接口冻结后再实施，避免角色规则与配置含义漂移；不要同时让两名实施者改同一策略文件。

- policy schema 升为 7，所有机器约束集中在该文件；文字契约和模板不得成为第二事实源。
- 新增执行偏好、严格可见要求及 implementation/all_delegated 范围、工具与授权检查、预算合并、复用及创建不确定处理。
- 按设计的四类映射增加通用主执行目标 visible_task；每个实施单元恰好一个主执行目标，根工作包统一风险与预算。角色名单仍为六个，不把通用执行者写成自定义角色身份。
- 修正核心模式原先“普通任务仅主 agent”的文字：机械/标准在用户明确授权且工具可用时允许可见实施通道；简单仍由主会话执行。这不改变安装模式和高风险隔离要求。
- 将 strong_max 明确迁移为职责席位和执行请求两个预算，允许有证据的架构澄清及一次修复后复审；计入总执行上限，不重置计数。
- 调整两次失败才能诊断的规则：具体能力不匹配可提前评估，仍记录证据、计预算，不能绕过分类与 strong 上限。
- 保留 Superpowers strict 唯一编排权；低上下文任务不加载可见通道参考文档。

真实试点使用单独、可恢复的小型测试工程，不直接拿用户其他业务工程做试验。创建前列出具体项目、目标模型、文件主责与验收；先确认有明确创建授权及目标项目。具体模型组合以当前宿主可用定义为准，不探测账号隐藏数据。

试点顺序：

1. 简单主会话任务：不创建子任务。
2. 一个明确授权的可见任务：确认请求模型/推理、工程基线和正式就绪 ID。
3. 同一任务的直接修复：复用 ID，传增量目标，执行次数累计。
4. 两个互斥实施工作包：默认最多两个并行，分别交付后由主协调者集成，验证最终树。
5. 模型不可用：模拟测试必须验证无静默替换；真实试点只记录自然遇到的拒绝，不为制造失败消耗模型额度。

桌面工具或可见任务授权缺失时，记录未验项目；契约测试不冒充真实试点通过。不得自动开通连接、创建无关项目、移动工程或复制凭据。

## 4. 必须覆盖的测试矩阵

| 领域 | 核心场景 |
| --- | --- |
| 配置 | v1读入、v2往返、未知版本/角色/字段、部分模型映射、继承加模型覆盖拒绝、非法effort、重复覆盖 |
| 路由解析 | 任务覆盖/角色覆盖/能力档顺序；模型与effort独立；主会话不虚报切换 |
| 迁移 | 旧有效effort保留、干运行零写入、备份失败不改安装、中途失败原字节/权限恢复、重复升级零写入 |
| 工件安全 | 修改冲突、链接/硬链接拒绝、未知state字段、认证/session不读取、公开导出白名单 |
| 模式 | core普通可见执行仍为core；enhanced与桌面工具独立；degraded不可被可见通道绕过 |
| 权限 | 可见只读提示不等同sandbox；高风险必要审查保留；implementation允许内部只读关口，all_delegated在缺可见只读能力时阻塞 |
| 授权与工具 | 工具存在无授权不创建；项目错配拒绝；模型/effort拒绝不替换；clientThreadId未就绪不继续；结果不明先对账 |
| 预算 | 内部/可见合计；继续/重试/升级计数；strong席位与请求分别计；澄清/修复后复审有界；重分类不清零；拆分子包继承根；超限需明确扩展；用户直接续跑纳入可观察对账 |
| 复用与集成 | 直接修复复用；陈旧/无关任务不复用；主责冲突串行；两棵树通过不等于最终集成通过 |
| 兼容 | status v1字段树、退出码；state v1；原CLI参数；Superpowers strict不派发；跨设备导入提示 |

纯文档规则使用契约测试固定关键冲突与示例；这些测试仅证明政策一致性，不证明模型一定遵循。真实副作用用隔离试点核对，不新增后台拦截系统。
