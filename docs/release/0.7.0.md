# Model Economy v0.7.0

## 简体中文

本次正式版聚焦可见任务派发契约与更细的模型配置。插件仍是社区开源项目，不代表 OpenAI 官方产品，也不是自动强制执行的后台调度器。

### 主要变化

- 六角色可以分别设置模型与推理强度。`--role-model ROLE=MODEL` 覆盖能力档模型，`--reasoning ROLE=LEVEL` 独立设置推理强度。继承档案不接受局部模型覆盖。
- 新安装默认：架构/终审 high，实现/审查 medium，探索/批处理 low。普通升级保留旧安装实际合法的推理强度，不强行套用新默认。
- 在用户授权且宿主工具支持时，可将机械/标准任务交给侧边栏可见任务；直接修复优先继续原任务。指定模型不可用时停止，不静默替换。简单任务仍在主会话完成。
- 内部代理与可见任务共享根工作包预算：最多三个新执行上下文、六次执行请求，默认并发两个；strong 职责席位和执行请求分别计数。以上均为策略级上限。
- 明确工作树基线、文件主责、待创建状态、唯一协调者和最终集成检查；空白工作包模板随 Skill 提供。
- 核心/增强/降级模式及高风险角色隔离要求保留；完整 Superpowers 仅在用户明确授权时接管编排。

### 升级注意

1. 更新插件来源到 `v0.7.0` 并在宿主中更新插件；新会话使用更新后的 Skill。仅更新仓库不代表现有会话已经切换规则。
2. 使用可选六角色增强的用户，在仓库根目录先运行 `python3 plugins/model-economy/scripts/model_economy.py upgrade --dry-run`，确认后运行 `upgrade`，再执行 `verify`。核心模式无需安装六角色。
3. config 读取 schema 1/2、写入 schema 2；state/status JSON 保持 schema 1。迁移会备份受管理文件，冲突或非法文件失败关闭。旧 CLI 不读取 schema 2；回退前按安装指南恢复备份，不直接覆盖旧配置。
4. 如已启用全局路由，需明确执行 `enable-global-routing` 刷新受管理区块；普通 `upgrade` 不修改全局规则。未启用的用户无需新增此项。

### 验证与已知限制

- 发布前本地完整自动化套件通过，覆盖配置、迁移、生命周期、路由契约和公开结构；已有独立架构/契约终审记录。
- **维护者明确批准跳过真实可见任务试点并以正式版发布。真实任务创建、原任务续改、双工作树集成与复杂并行尚未验证，不记为测试通过。** 后续通过实际使用收集问题。
- 可见任务的模型字段只是请求配置，不证明实际模型或角色身份；可见只读提示不等于只读沙箱。缺少高风险所需隔离能力时仍不得声称完成完整高风险流程。
- 不承诺固定 Token 节省，不新增遥测、后台服务或角色级 Token 归因。本次没有提交官方插件目录审核。
- 附件 ZIP 是可重复生成的 Skills-only 分发包，不代表已获官方目录批准。问题请提交至仓库 Issues。

## English

This stable release focuses on visible-task contracts and finer model configuration. Model Economy is a community project, not an official OpenAI product or a runtime-enforced background scheduler.

### Changes

- Per-role model overrides (`--role-model ROLE=MODEL`) and independent reasoning (`--reasoning ROLE=LEVEL`). Inherited profiles reject partial model overrides.
- New-install defaults: architecture/final review high, implementation/review medium, exploration/batch low. Upgrades preserve existing valid effective reasoning settings.
- Authorized mechanical/standard work may use visible tasks when host tools support them. Direct fixes reuse the original task; rejected model requests stop rather than silently substituting. Simple work stays in the main task.
- Internal agents and visible tasks share policy-level limits: three new execution contexts, six execution requests, and two concurrent tasks by default. Strong-role seats and requests are counted separately.
- Explicit worktree baselines, file ownership, pending creation, one coordinator, and final integration checks, with a self-contained blank work-package template.
- Core/enhanced/degraded boundaries and high-risk isolation remain. Full Superpowers takes orchestration only with explicit user authorization.

### Upgrade

Update the plugin source to `v0.7.0`, update it in the host, and start a new task to pick up the Skill. Optional six-role users should run `upgrade --dry-run`, then `upgrade` and `verify` through the repository CLI. Core mode does not require six-role installation.

Config reads schema 1/2 and writes schema 2; state/status remain schema 1. Migration backs up managed files and rejects conflicts or unsafe input. Older CLIs cannot read schema 2: follow the installation guide to restore backups before rollback. Existing global-routing users must explicitly run `enable-global-routing` to refresh that managed block; ordinary upgrades do not change global rules.

### Evidence and limitations

The local automated suite passed before release, covering configuration, migration, lifecycle, routing contracts, and public structure; independent architecture/contract review is recorded.

**The maintainer explicitly waived live visible-task trials and approved a stable release. Live creation, continuation, two-worktree integration, and complex parallel behavior remain unverified—not passed.** Model fields are requests, not proof of model/role identity, and read-only prompts are not read-only sandboxes. High-risk isolation gates still apply.

No fixed token-savings claim, telemetry, background service, or role-level token attribution is added. The attached reproducible Skills-only ZIP is a distribution artifact, not evidence of official directory approval. No official directory submission was made for this release. Please report issues in the repository.
