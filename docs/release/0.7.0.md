# Model Economy v0.7.0

## 简体中文

这版主要管两件事：活儿交给谁，以及交出去以后别失联。顺手把升级时保留旧配置的工作也补上了，毕竟更新插件不该附赠一次“失忆”。

### 模型和思考强度，可以分开安排了

六个角色可以分别指定模型，也可以单独设置推理强度。写实现的不必跟架构师用同一档，查文件的也不必每次都沉思良久。

新安装默认是：架构和终审 `high`，实现和审查 `medium`，探索和批处理 `low`。已有安装走普通升级时，保留原来有效的设置，不替你擅自降档。

参数是 `--role-model ROLE=MODEL` 和 `--reasoning ROLE=LEVEL`。角色模型优先于能力档模型；继承式档案不接受局部模型覆盖。这些是请求配置，不是实际模型身份的鉴定证书，也不会切换当前主会话模型。

### 分出去的任务，不用每次重新招人

你明确授权、宿主工具也支持时，合适的机械或标准工作可以交给侧边栏独立任务。文件归谁改、从哪个版本开始、用什么模型，都要交代清楚。刚交付的改动需要修补，优先在原任务继续。

模型请求被拒绝就停下来说明，不偷偷换一个。任务还在创建中，就先查状态，不因为等得着急再开一份。简单任务留在当前会话：改个配置，暂时不需要成立专项小组。

内部代理和可见任务共用策略级预算：最多三个新执行上下文、六次执行请求，默认并发两个。续改和重试也记账；拆工作包不能把账清零。strong 角色席位与请求次数分开算，每个获准 strong 角色最多两次。这些是工作规则，不是平台替你锁死的用量额度。

### 升级时，先留好退路

配置现在写入 schema 2，仍能读取 schema 1；state 和 status JSON 保持 schema 1。旧配置迁移前会备份受管理文件，保留模型映射和实际合法的推理强度。遇到冲突或不安全文件就停止，写入事务失败则恢复旧工件。

已安装用户可以把 [README 中的通用更新指令](https://github.com/BottleYo/model-economy#already-installed-ask-codex-to-update-it)交给另一台电脑的 Codex。手动升级六角色配置时，先 `upgrade --dry-run`，确认后 `upgrade`，再 `verify`。核心模式不必顺手装六角色。

以前启用了全局路由，才需再运行 `enable-global-routing` 刷新受管理区块；普通 `upgrade` 不碰它。旧 CLI 读不了 schema 2，回退要按安装指南成套恢复备份，别只改一个版本数字。更新插件后新建任务，旧对话不会因为仓库更新就自动“换脑”。

### 这次测了什么，没测什么

发布时本地 254 项自动化测试通过，macOS、Linux、Windows 的 Python 3.11/3.12 CI 通过；已有独立架构和契约终审记录。

**真实任务创建、原任务续改、双工作树集成与复杂并行尚未验证。维护者选择跳过这轮真实派发试点，以正式版发布，后续在实战中收集问题。跳过就是跳过，不算测试通过。**

高风险任务仍需满足角色隔离要求；一句“请只读”不等于只读沙箱。核心、增强和降级模式的边界没有取消。只有你明确要求完整 Superpowers 时才交出编排权，不让两套流程抢方向盘。

没有固定 Token 节省承诺，没有新增遥测、后台服务或角色级 Token 归因。Model Economy 是免费社区项目，不是 OpenAI 官方产品；本次未提交官方目录审核。附件是可重复构建的 Skills-only 分发包，不是上架通行证。遇到问题，欢迎带复现步骤来 Issues。

## English

This release is mostly about who gets the job, and keeping track after handing it off. It also makes upgrades preserve your settings. A plugin update should not come with complimentary amnesia.

### Pick the model and reasoning level separately

Each of the six roles can have its own model and reasoning setting. Implementation does not need the architect's reasoning level, and a file lookup does not always need a long think.

New installs use `high` for architecture/final review, `medium` for implementation/review, and `low` for exploration/batch work. Normal upgrades preserve existing valid settings rather than quietly dialing them down.

Use `--role-model ROLE=MODEL` and `--reasoning ROLE=LEVEL`. Role overrides take precedence over capability-tier models; inherited profiles reject partial model overrides. These fields request a configuration, not certify model identity or switch the current main chat's model.

### A follow-up fix should not need a new hire

With your authorization and host-tool support, suitable mechanical or standard work can run in visible sidebar tasks. File ownership, starting point, and requested model must be clear. Direct fixes should return to the original task when possible.

A rejected model request stops the route; it does not trigger a quiet substitution. A task still being created needs a status check, not a duplicate. Simple work stays in the current chat. Changing a setting does not need a committee.

Internal agents and visible tasks share policy-level limits: three new execution contexts, six execution requests, and two concurrent tasks by default. Continuations and retries count; splitting a work package does not reset the bill. Strong-role seats and requests are separate, with at most two requests per permitted strong role. These are workflow rules, not platform-enforced quotas.

### Keep a way back when upgrading

Config now writes schema 2 and reads schemas 1/2; state and status JSON stay at schema 1. Migration backs up managed files, preserves model mappings and valid effective reasoning, rejects conflicts or unsafe files, and restores old artifacts if the write transaction fails.

Use the [reusable update prompt in the README](https://github.com/BottleYo/model-economy#already-installed-ask-codex-to-update-it), or run `upgrade --dry-run`, then `upgrade` and `verify` for an existing six-role setup. Core-mode users do not need to add six roles. Refresh global routing with `enable-global-routing` only if it was already enabled; ordinary upgrades leave it alone.

Older CLIs cannot read schema 2. Follow the installation guide to restore a complete backup before rollback; changing a version number is not a migration. Start a new task after updating the plugin.

### What passed, and what did not run

At release, 254 local automated tests passed, along with Python 3.11/3.12 CI on macOS, Linux, and Windows. Independent architecture and contract reviews are recorded.

**Live task creation, continuation, two-worktree integration, and complex parallel workflows remain unverified. The maintainer waived live dispatch trials and approved a stable release, with feedback to come from real use. Waived does not mean passed.**

High-risk isolation gates still apply. A read-only prompt is not a read-only sandbox, and core/enhanced/degraded boundaries remain. Full Superpowers takes over only on your explicit request; two workflows should not fight over the steering wheel.

No fixed token-savings promise, telemetry, background service, or role-level token attribution was added. This is a free community project, not an official OpenAI product. No official directory submission was made. The reproducible Skills-only ZIP is a distribution package, not directory approval. Reproducible issue reports are welcome.
